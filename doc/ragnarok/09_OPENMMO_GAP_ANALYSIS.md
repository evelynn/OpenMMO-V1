# 09. OpenMMO 갭 분석과 채택 결정

01~08 문서의 판단을 한 장에 모았다. **이 문서만 읽어도 무엇을 만들지 알 수 있어야 한다.**

## 1. 전제: OpenMMO는 RO의 클론이 아니다

세 가지가 이미 다르게 결정되어 있고, 이를 뒤집는 제안은 채택하지 않는다.

| 축 | OpenMMO | RO |
|----|---------|-----|
| 캐릭터 | 능력치 3~18, 4d6-drop-lowest, 총합 72 고정. **생성 시 확정** | 1~130, 레벨업마다 포인트 배분 |
| 월드 | 32km × 32km **이음매 없는 절차적 월드** | 개별 맵 파일의 그래프 |
| 대상 규모 | **동시 5,000명**, 서버 권위 + 몬스터 AI는 소유자 클라이언트 | 채널/맵 분산 |

여기에 하나 더 — **에이전트-인간 동등성**. 사람이 할 수 있는 것은 봇도 할 수 있어야
하고, 그 역도 같다. 이 제약은 아이템 강탈·자동화 유인이 큰 시스템을 걸러낸다.

## 2. 현재 구현 인벤토리

이미 있는 것을 모르면 중복 설계를 한다.

| 영역 | OpenMMO 현황 |
|------|--------------|
| 전투 | D&D식 서버 권위 판정, `guard`/`attackBonus`/`damageRoll`, 애니메이션 기반 타이밍 3종 |
| 성장 | 단일 레벨, `xp = 20·2^(n-2)`, 파티 분배(+25%/인, 150m, 동일 층) |
| 스킬 | `SkillId::Fishing` 하나, 레벨 0~30, `100·level²` |
| 디버프 | CSV 구동 2종(식중독·출혈), 배수 곱연산, 서버 판정 |
| 장비 | `EquipSlot` 14종, **무게 제한 강제** |
| 강화 | 인챈트 주문서 — 확정 구간 + 실패 시 **장비 파괴** (RO 제련과 동형) |
| 아이템 | 25컬럼 CSV, 아이콘/월드모델/카테고리/드랍/가격 |
| 몬스터 | 42컬럼 CSV, **플레이어 추종 앰비언트 스폰**(`data-src/world.json` + 인당 캡 30), 던전 depth 가중치. 존 파일의 `monsterSpawns`는 서버가 읽지 않는다 |
| 던전 | 시드 결정적, 최대 20층, 보스, 상자 티어 |
| 월드 | 절차적 지형/강/도로/식생, 하우징(다층·가구·문), 낮밤·쌍월, 존 시스템 |
| 사회 | 파티, 친구, 귓속말, 거래, 딜(haggle), 노점, 상인, 급여, 공연 |
| 생활 | 낚시, 채집, 허기, 요리, 캠프파이어 |
| 운영 | 관리자 명령(공지/추방/뮤트/밴/소환), 맵 에디터 |
| 에이전트 | LLM NPC 클라이언트 — 사람과 동일 프로토콜 |

**없는 것**: 퀘스트, 창고, 워프/세이브 포인트, 길드, PvP, 스킬 트리(전투),
레벨 차 EXP 페널티, 카드/슬롯, 속성·종족 축, 제작(단조·조제).

## 4. 결정을 관통하는 기준

채택된 항목을 다시 보면 공통점이 보인다.

1. **기존 데이터 구조에 컬럼 하나로 붙는가** (7, 8, 11, 16, 17).
2. **월드를 쓰게 만드는가** — 32km를 만들어 놓고 안 쓰면 손실이다 (1, 2, 4, 5, 9).
3. **나중에 못 넣는 것인가** — 일일 한도, 개인 쿨다운, 거래 수수료, 시간 4분할은
   전부 **뒤늦게 추가하면 너프로 인식되거나 구조를 갈아엎어야 한다** (3, 12, 14, 20).
4. **5,000 동접에 새 비용을 얹지 않는가** (26, 31, 33 기각 사유).

기각된 항목의 공통점도 하나다: **RO가 20년에 걸쳐 쌓은 인플레이션 대응 레이어**
(섀도우 기어, 슬롯 추가, 4차 트레잇, 길드 확장 판매)는 신규 프로젝트에 필요 없다.
그 레이어들이 해결하려던 문제가 아직 존재하지 않기 때문이다.
