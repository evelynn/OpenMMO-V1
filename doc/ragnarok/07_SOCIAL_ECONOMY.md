## 1. 파티

- 초대 기반. **같은 맵**의 멤버끼리 EXP·아이템 균등 분배(Even Share) 선택 가능.
- 분배 방식이 EXP 공식의 인자다 — 파티 구성이 획득량을 직접 바꾼다.
- 같은 맵 조건이 핵심. 이게 없으면 "다른 데서 노는 사람에게 경험치 흘리기"가 된다.

## 2. 길드

| 항목 | 규칙 |
|------|------|
| 인원 | 기본 **16명**(길드장 포함), Guild Extension 스킬로 iRO 기준 최대 **56명** |
| 길드 스킬 | 길드 단위 스킬 트리. **액티브 스킬은 길드장만** 사용 |
| 공식 승인 | Official Guild Approval 스킬이 있어야 엠페리움에 피해를 줄 수 있다 |
| **칭호(Title)** | 최대 **20개**를 길드장이 정의. 초대·추방·**길드 창고 접근** 권한이 칭호에 붙는다 |
| 길드 창고 | 존재. 접근 권한은 칭호로 통제 |

칭호가 곧 **권한 체계(RBAC)**라는 점이 설계상 깔끔하다. 역할 이름과 권한을 하나로
묶어 길드장이 조직도를 직접 만들게 한다.

길드가 **자체 성장 축(길드 스킬)**을 갖는다는 점이 중요하다. 길드는 채팅방이 아니라
투자 대상이 된다.

## 3. 공성전 (War of Emperium)

- 길드가 **성(Castle)을 점령**해 본거지로 삼고 혜택을 얻는 정기 이벤트.
- 성 안의 **엠페리움**을 파괴하면 점령. 승인 스킬이 있는 길드만 타격 가능.
- 길드원은 성 밖 **깃발**을 클릭해 성 내부 지정 위치로 즉시 이동.

정해진 시간에만 열리는 대규모 PvP + 영구적 소유권 = MMO 길드 콘텐츠의 원형.
5,000 동접 관점에서는 **국지적 초고밀도 전투**의 대표 사례이기도 하다.

## 4. 배틀그라운드 / PvP

| 모드 | 형식 |
|------|------|
| Tierra Valley | 단판 |
| Flavius | 3판 2선승 |
| KVM (Kreiger Von Midgard) | 단판 |

- 보상은 **배지**: Tierra = Bravery, Flavius = Valor, KVM = Reward Point.
  배지는 전용 장비와 교환하며, **배지 종류를 섞어서 지불할 수 없다.**
- 주간 특정 시간대에 배지 **2배** — 참여 시간을 몰아주는 장치.
- 일반 PvP는 모드에 따라 페널티가 다르다 (Yoyo = 무손실, Nightmare = EXP 손실 +
  1% 아이템 드랍).

## 5. 경제

### 제니 획득

주 수입원은 **NPC 판매**와 **플레이어 간 거래**다. 위키가 명시하듯, 실질적인 부는
"이미 돈이 많은 고참 플레이어에게 파는 것"에서 나온다 — 즉 **아이템 가치의
플레이어 시장 형성**이 경제의 본체이고 NPC 상점은 바닥값 역할.

### 노점 (Vending)

- 상인/슈퍼노비스 계열이 **푸시카트 장착 시** 개설. 카트 안 물건만 판매 가능.
- 가격 상한 **1,000,000,000 제니**.
- **수수료: 10,000,000z 초과 물건에 5%** (판매자 95% 수령) — 고액 거래 전용 싱크.

### 상인 스킬이 곧 경제 스탯

| 스킬 | 효과 |
|------|------|
| **Overcharge** | NPC 판매가 상승 (기본은 판매가의 50%만 받음) |
| **Discount** | NPC 구매가 하락 (Lv10에서 레드포션 40z → 38z) |

플레이어 캐릭터의 스킬이 **거래 환율 자체를 바꾼다.** 그래서 상인이 파티에
없어도 존재 이유가 있고, 부캐로 상인을 키우는 문화가 생긴다.

## OpenMMO 적용

**현재 상태**
- 파티: 있음. 초대/수락, EXP 분배(멤버당 +25%, 반경 150m, 같은 층),
  파티 채팅, 소환(`PartySummonToast`).
- 친구, 귓속말, 거래(trading), 딜(haggle: `ActiveDeal`, 매수/매도 % 보정),
  노점(`stall.rs`), 상인 NPC(`merchants.csv`의 `sellRatePercent`, `catalog`),
  급여(salary), 팁 모자(`tip_hat`)까지 이미 있다. **경제 시스템의 밀도가 높다.**
- 길드, 공성전, 배틀그라운드, PvP는 **없다**.
- 관리자 모더레이션(`/kick`, `/mute`, `/ban`)은 있다.

**가져올 것**
1. **길드 = 투자 대상이라는 구조.** 단순 명단 기능으로 만들면 채팅 채널에 그친다.
   최소한 "길드 창고 + 길드 단위 성장치" 하나는 처음부터 넣어야 길드가 유지된다.
   OpenMMO에는 하우징이 있으므로 **길드 하우스**가 자연스러운 형태다.
2. **고액 거래 수수료(5%).** 이미 딜/노점 시스템이 있어 붙일 자리가 있고,
   플레이어 간 거래가 활발해질수록 커지는 **자동 스케일 제니 싱크**다.
   인플레이션 대책을 나중에 붙이면 이미 늦는다.
3. **경제 스킬.** OpenMMO는 CHA 스탯과 haggle이 이미 있다. RO의 Overcharge/Discount를
   "CHA + 거래 스킬 레벨이 환율을 바꾼다"로 흡수하면, 전투 외 성장 축이 생긴다.
   `skills.rs`의 `SkillId`에 `Trading`을 추가하는 정도로 시작 가능.

**변형할 것**
- 공성전: 32km 이음매 없는 월드 + 하우징이 이미 있으므로, RO식 고정 성이 아니라
  **거점 점유(하우징 부지/랜드마크)** 형태가 이 프로젝트에 맞는다. 다만
  국지 밀집 전투의 성능 검증이 선행되어야 한다 (아래 성능 주의).
- 배틀그라운드 배지 → 이미 있는 통화/아이템 체계로. 새 통화를 늘리기 전에
  기존 `currency` 카테고리로 표현 가능한지 먼저 본다.

**기각할 것**
- 길드 인원 상한을 스킬로 파는 구조(16 → 56). 과금·성장 축이 뒤엉킨 레거시다.
- PvP Nightmare 모드의 아이템 드랍. 에이전트와 인간이 같은 규칙으로 노는 월드에서
  아이템 강탈은 봇 farming 유인을 극단적으로 키운다.

**성능 주의 (5,000 동접)**
- 공성전·배틀그라운드는 **한 지점에 수백 명**을 모은다. OpenMMO의 브로드캐스트는
  관심 영역 기반이어야 하며, 밀집 시 메시지량이 O(N²)로 폭발한다. 도입 전에
  반드시 부하 테스트를 선행하고, 인원 상한과 시야 컬링을 먼저 설계한다.
- 길드/파티 목록 같은 조회는 접속자 전체를 훑지 않도록 인덱스를 갖춰야 한다.
